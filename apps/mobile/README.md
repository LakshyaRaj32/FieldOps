# apps/mobile (reserved)

The FieldOps React Native application. It serves both field workers and managers, with
navigation based on the user's role.

**Status:** reserved. The app will be generated in **Version 1** with the official React Native
Community CLI. It is not hand-written, so the Android project (Gradle, manifest, Kotlin entry
points) exactly matches what the React Native release expects.

## Planned stack

React Native (New Architecture, Hermes) · TypeScript (strict) · React Navigation · Redux Toolkit ·
RTK Query · SQLite · MMKV · NetInfo · Reanimated · Kotlin native modules (Turbo Modules)

## Primary platform

**Android.** The native subsystems (foreground location service, background work) are written in
Kotlin. Native capabilities sit behind TypeScript interfaces, so an iOS implementation could be
added later without changing feature code.

## Planned source layout (created in V1, filled in over later versions)

```text
apps/mobile/
├── android/                 Generated by the RN CLI; Kotlin modules added in V7
└── src/
    ├── app/                 App root, providers, navigation containers
    ├── features/            Vertical feature slices (auth, jobs, location, messaging, ...)
    │   └── <feature>/
    │       ├── screens/
    │       ├── components/
    │       ├── hooks/
    │       └── data/        Feature-specific SQLite repositories and RTK Query endpoints
    ├── core/                Cross-feature infrastructure
    │   ├── api/             HTTP client and RTK Query base API (V2)
    │   ├── auth/            Session and secure token storage (V2)
    │   ├── db/              SQLite connection, migrations, reactive queries (V5)
    │   ├── sync/            Outbox and sync engine (V6)
    │   ├── native/          Typed wrappers around Kotlin Turbo Modules (V7)
    │   └── storage/         MMKV key-value storage
    ├── store/               Redux store setup (UI/session state only)
    └── ui/                  Design system primitives
```
